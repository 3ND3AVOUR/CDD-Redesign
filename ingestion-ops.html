Routing & throughput

Every record a source hands over gets read once, matched against a rule, and sent down one of three lanes for processing. This is that decision, made live, source by source.

How routing works, in order: (1) a source delivers a batch of records → (2) the router inspects the format of each record → (3) it's matched against the rules below, top to bottom, first match wins → (4) the record is handed to that lane's queue for the detection engine to pick up. A record only sits in the router itself for milliseconds — the latency KPI below is that hop, not the full ingestion time.

Routing rules — evaluated top to bottom

What decides which lane a record lands in.

#If a record looks like…It goes to…Because
1A structured row — database record or API/JSON payloadType-1Already field-delimited, no pre-processing needed — fastest lane
2An unstructured file — PDF, DOCX, scanned imageType-2Needs an OCR / text-extraction pre-pass before detection can read it
3A bulk export — over 50MB or 100K+ rows in one deliveryType-3 (batch)Chunked into smaller pieces so one big drop can't starve everything else
—Anything from a source that's currently disconnectedHeld, not routedQueued at the source; nothing to route until it reconnects
