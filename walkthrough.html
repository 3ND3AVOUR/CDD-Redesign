1What this is

CDD stands for Confidential Data Discovery. In plain terms: it connects to the places your business keeps data, checks that data for anything sensitive — names, ID numbers, card numbers, health records — and helps you review, trust, and report on what it finds. That's it. Everything in this prototype is one of those three jobs: connect, check, or make sense of what was found.

Earlier versions of this build organized the product around five internal engineering-team names — CITADEL, RANGER, SENTRY, LEGION, SHIELD — because that's how the real system is staffed. v3.2 drops all five. Nobody using this product needs to know which team owns which screen; they need to know what to do next. So the whole thing is now organized the same way the work actually happens, one stage at a time: Connect → Watch → Detect → Trust → Comply → Manage.

2How the pieces fit together

You never have to think about this to use the product — but it's useful to know why checking a source involves more than one step.

Connect+ Watch→ Detect→ Findings
Connect brings a source in and keeps the connection alive. Watch is the logic that decides what actually changed and whether it's worth a closer look, so nothing gets re-checked from scratch every time. Detect is the engine that does the actual checking and produces a finding. Trust is where that detection model is trained and tested, so its accuracy number holds up. Overview (Home) is the platform all of this runs on, and the screen you land on first.

3Every screen, mapped

19 main pages, one flat list in the sidebar, grouped into 7 stages — no separate "projects" to click into first. Most of those pages are hubs: instead of a separate sidebar entry for every view, related views live as tabs inside one page (Overview / Health / Scans / Failed items, all inside Sources, for example). Tabs are deep-linkable too — a link can point straight at Sources/index.html#health and land on that exact tab. Connecting a source isn't a page at all anymore — it's a button that opens a modal wherever you are, so it doesn't even cost a click of navigation. This is also the exact order of The Journey.

12 of the 19 are the original business-user pages — the simplified core this rebuild has been converging on all along. The other 7 (Search, Ingestion ops, Delta ops, Detection infra, Model ops, Pipeline, and Platform admin) were added on request, to bring back every one of the 32 requirement screens the earlier IA & requirements audit had flagged as unrepresented — mostly SRE/platform-engineering depth (queue lag, GPU cost, DLQ replay, CDC override, drift charts) that a business DPO never needs but a Platform Ops admin does. Rather than bolt on 32 new sidebar entries, each was folded in as the technical "deep pair" of an existing stage, the same base ↔ deep pattern the original 65-screen spec itself used — so Pipeline sits next to System health under Manage, Detection infra sits next to Detection under Detect, and so on. All 7 are role-gated to admin/compliance so a DPO's nav stays exactly as short as before.

5One journey, start to end

v3.0 built one 47-screen tour. v3.1 tried three separate persona-specific tours. v3.2 went back to one — The Journey — in the order a real rollout actually happens (connect → watch → detect → trust → comply → manage), with each hub's tabs riding along inside its step rather than counting as steps of their own. Connect a source isn't a step at all any more — it's a button on the Sources screen. It's now 19 steps, not 12: the 7 admin/compliance-only deep-ops pages ride along as their own steps too. The journey doesn't auto-filter these by role the way the sidebar nav does — but you can hide any step yourself with the "Customize steps" toggle on The Journey page, so a DPO can trim it back to the 12-step business view in a couple of clicks and it'll stay that way. A banner at the top of every screen — not just while "in a journey" — shows the stage, what that screen does, and one click to the next step. Browsing from the sidebar still works exactly the same; the banner is just always there too.

6What changed from the original spec

The original documents and files describe a much bigger, more technical product — already built out as 65 screens across five internal engineering-team names. This prototype is a deliberate, simplified rebuild of the same idea, aimed at a business user instead of an engineer — and v3.2 is the most simplified version yet. Here's the honest comparison.

7What's not here yet, and what changed in v3.2

Being specific about both, on purpose — a simplified build should say plainly what it left out, not just what it kept.

🚫 Cut or folded away, then partly brought back

  • Duplicate or near-duplicate views — Data inventory and Posture trends overlapped with Coverage and Compliance assurance closely enough to drop without losing information. Still cut — genuine duplicates, not brought back.
  • Deeper configuration screens — Detection settings, Alert rules, Sensitivity types, Test data, Drift monitoring, Review queue. Originally cut as one level deeper than a seamless connect-to-manage story needs; Drift monitoring, Review queue, and Test data are now back as tabs on Model ops, and Alert rules as a tab on Delta ops.
  • Secondary catalog/detail views — Browse integrations, Throughput, Data copies, Trends, Stuck items, Activity (change log), Savings report. Search is now back as its own page; Browse integrations is now back as a real Catalog tab on Sources (14 named integrations, not a "10+" stat); Throughput and Data copies (as "data sprawl") are now back on Detection infra; Savings report is now back on Delta ops; Activity (change log) is now back as a platform-wide Audit log on Platform admin.
  • Deeper admin surfaces — Pipeline health and Queue depth, Data encryption, Where data lives. All of these are now back — Pipeline health & Queue depth on the new Pipeline page, Data encryption on Platform admin.
  • Onboarding wizard — the flow now starts directly at the Dashboard instead of a separate "welcome" screen first. Still cut.
  • Connect a source as its own page — not cut, just no longer a standalone screen or a journey step: it's now a button on Sources that opens the same wizard as a modal, so getting there costs zero navigation.
  • Five separate sidebar entries per group, now one hub with tabs — not cut, just no longer a standalone page: Connections, Connection health, Failed items, and Scans are now 4 of the 6 tabs inside Sources (History and Catalog are new — see below); Compliance assurance and Regulation coverage are now the 2 tabs inside Compliance; Reports and Evidence packs are now the 2 tabs inside Reports & evidence; Alerts and Capacity are now the 2 tabs inside System health; Admin, Roles & permissions, and Data retention are now the 3 tabs inside Admin; Changes and Why wasn't this checked? are now the 2 tabs inside Monitoring; Detection, Coverage, and By source are now 3 of the 4 tabs inside the Detect hub (Assurance is new).

✅ Added or changed in v3.2

  • A real dashboard — the old Home became a customizable tile grid: pick which KPIs you see, reorder them, and every tile carries a trend sparkline. Your layout is saved per browser.
  • Consolidated hubs with tabs — related screens live as tabs inside one page instead of separate sidebar entries. Tabs are deep-linkable — a link can jump straight to one, e.g. Sources/index.html#health.
  • 7 admin/compliance-only deep-ops pages — Search, Ingestion ops, Delta ops, Detection infra, Model ops, Pipeline, and Platform admin, added on request to close out the remaining screens from the original spec (see the IA & requirements report). Each is the technical "deep pair" of an existing business-facing page and role-gated out of a DPO's nav.
  • Connect a source is now a modal, not a page — click it from the sidebar, the Dashboard, or the Sources button and the wizard opens right on top of whatever you were looking at. Finish it and you land on Sources' Scans tab with your new source already checking; close it and you're exactly where you were.
  • A real schedule, not just a frequency — Weekly asks which day, Monthly asks which day of the month (with a stated rule for months that don't have it), and there's now a One time option with its own date. The chosen schedule shows up right on the Scans tab.
  • Every completed source can be rechecked, not just some — every "Done" row on Scans now has both View results and Check again; previously most sources only had one or the other.
  • A History tab on Sources — every past scan per source, with what changed run to run, plus a deduplicated "consolidated" total so re-finding the same items across scans doesn't get counted twice.
  • View results knows where it's going — clicking it from Sources now lands on Findings scoped to that one source, with a banner and a one-click way back to Sources instead of the full unfiltered list.
  • No more project names — CITADEL, RANGER, SENTRY, LEGION, SHIELD are gone from the product. The sidebar is one flat list grouped by what each stage does.
  • Plain persona names — Compliance and IT Admin became Compliance Ops and Platform Ops, matching Privacy Ops.
  • Full-bleed layout — the shell now fills the screen edge to edge instead of sitting centered with margins.
  • A real guided walkthrough, not just a list — a "▶ Start walkthrough" button in the sidebar launches an actual product tour: Previous/Next walk the real 19-step sequence, a running "Pipeline so far" checklist tracks genuine progress (it only checks off "Source connected" once you actually complete the wizard), and the first four steps start from a real empty state — nothing connected, nothing to report — instead of jumping straight into the fully populated demo.
  • A "Manual only" schedule — connecting a source no longer forces a recurring schedule; you can say "I'll check it myself" and nothing runs automatically after the first check.
  • Tenants & roles, with a real second-approver flow — Platform admin gained a Tenants tab where creating a tenant (or rotating an encryption key) needs a different admin to approve it before it takes effect, logged automatically to a new platform-wide Audit log.
  • Bring-your-own-key — the connect wizard now has an optional field to attach a customer-managed encryption key instead of the platform-managed default.
  • PII, PHI, PI, PFI, Other — consistently, everywhere — PHI (health data) used to be buried inside "Other"; it's now its own category, shown identically on both Findings and Elements, including a Category column and filter on Findings that didn't exist before.
  • Removed the version dropdown — v1.0 through v3.2 no longer sits in the header; this is simply the current build.
